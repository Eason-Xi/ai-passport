# 限定猜拳 —— FoloToy AI Passport

基于《赌博默示录》（开司）"限定猜拳"的多人联机派对游戏。每位选手手里一台 AI Passport，
在自己的设备上暗中出牌；另有一台 AI Passport 当**庄家**（发牌兼裁判）。所有设备连现场 Wi-Fi，
通过一台电脑上运行的**电脑服务**（`tools/kj_hub`）联机——不需要用 USB 线连电脑。电脑上的看板实时
显示每位选手的昵称、剩余的石头 / 剪刀 / 布、星星，以及对决中双方已经扣下的暗牌，并把每一局记录下来、
可以导出 CSV。看板只给庄家和观众看，不给选手看。

## 规则（与原作一致）

- 每人开局 **石头、剪刀、布各 4 张**，**星星 3 颗**。
- 两人对决：各自扣下一张牌，同时亮出。石头胜剪刀、剪刀胜布、布胜石头。胜者从败者处拿走
  **1 颗星**，平局不动；出过的牌作废。
- 星星**归零立即出局**。
- **12 张牌全部出完且星星 ≥ 3 颗即过关**；出完但不足 3 颗即**失败**。
- 庄家宣布结束（原作的时限）时，仍有手牌的人判负。

开始一场对决有两种方式：

- **碰拳**：两个人面对面，同时**长按 OK**。庄家按两人按下的时刻配对，双方屏幕显示对手的昵称，
  3 秒倒计时后自动开打；认错人了，倒计时内长按 OK 取消。
- **名单挑战**：在"选择对手"里挑一个空闲的人发起挑战，对方 20 秒内应战。

## 需要准备

| 物品 | 说明 |
| --- | --- |
| 每位选手一台 AI Passport | 人数不限；一台庄家最多 128 个座位。 |
| 再多一台 AI Passport 当庄家 | 同一份固件，持有唯一可信的赌局状态。 |
| 一台电脑 | 运行电脑服务（只需要 Python 3.9+，不用装任何依赖）。插上电源、关掉睡眠。 |
| 一个 2.4 GHz Wi-Fi | 推荐自带路由器，电脑最好用网线接入。访客网络、需要网页认证或开了"AP 隔离"的 Wi-Fi 通常不行；手机热点只适合少量设备调试。 |
| 每位选手一部手机（可选） | 扫码登记昵称；也可以在电脑看板上直接给设备起名。 |

只有两台设备也能玩：一台庄家 + 一位选手，在庄家上添加**电脑选手**陪练。

## 快速开始

1. 给每台设备刷入 `build/FoloToy-AI-Passport-full.bin`（见[编译与刷机](#编译与刷机)）。
2. 在电脑上启动电脑服务，浏览器会自动打开看板：

   ```bash
   python3 tools/kj_hub/hub.py
   ```

   macOS 第一次运行会问是否允许 Python 接受传入的网络连接，选"允许"；Windows 请把当前网络设成"专用网络"。
   详见 [电脑服务说明](tools/kj_hub/README.zh_CN.md)。
3. **配网**（每台设备只需一次）：第一次开机，设备开出热点 `KJ-XXXX` 并在屏幕上显示二维码。用手机**相机**
   扫码连上热点，弹出的网页里选择现场 Wi-Fi、输入密码（没弹出就在浏览器打开 `192.168.4.1`）。
   设备连接成功后自动重启，之后开机自动连这个 Wi-Fi。
4. 设备连上 Wi-Fi 后会自动找到电脑服务，首页左上角显示"电脑服务已连接"。
5. 庄家设备在首页选择"我是庄家 · 开设赌局"。看板上会出现这个赌局。
6. 选手设备选择"我是选手 · 加入赌局"。还没有昵称时先显示**登记二维码**：用**微信扫一扫**（或手机相机）
   打开网页，填写昵称（最多 8 个汉字或 16 个字母），设备上马上显示"欢迎"。然后在赌局列表里选中庄家的
   赌局，按 **OK** 入座。手机必须和电脑连同一个 Wi-Fi 才能打开登记页。
7. 在看板或庄家菜单里"开始赌局"。选手各自碰拳或挑战、对决、守住星星；看板实时跟踪每一张牌。

重启后会预选上次的角色；选手会自动回到上次的赌局和座位。

## 设备界面与按键

▲ / ▼ 按下即响应；OK 单击确认；长按 OK（0.5 秒）用于返回、撤回、拒绝、取消——只有手牌页的长按是**碰拳**。
每个页面底部都有本页的按键提示，右上角显示电量（读不到电量计时显示 `--`）。

| 页面 | ▲ / ▼ | OK | 长按 OK |
| --- | --- | --- | --- |
| 配网（热点二维码） | — | — | 先跳过 |
| 首页 | 在选手 / 庄家 / 设置之间移动 | 确定 | — |
| 设置 | 在登记昵称 / 重新配网 / 返回之间移动 | 确定 | 返回首页 |
| 登记昵称（二维码） | — | 换一个二维码 | 返回（选手可以先跳过） |
| 寻找赌局 | 在赌局之间选择 | 入座 | 回到首页 |
| 已入座 | — | — | 离座（庄家那边保留座位） |
| 手牌主页 | — | 选对手（名单挑战） | **碰拳** |
| 碰拳中 | — | — | — |
| 碰拳配对成功（倒计时） | — | — | 取消（认错人了） |
| 选择对手 | 在可挑战的人之间移动 | 发起挑战 | 回到手牌 |
| 等待应战 | — | — | 撤回挑战 |
| 收到挑战 | — | 应战 | 拒绝 |
| 出牌 | 在手里还有的牌之间移动 | 扣下这张牌（不能反悔） | 出牌前放弃这场对决 |
| 亮牌 | — | 继续 | — |
| 过关 / 出局 / 失败 | — | — | — |
| 庄家面板 | 在菜单之间移动 | 执行（结束、新一局、清空需要再按一次 OK 确认） | 取消确认 |
| 庄家：选手名单 | 翻看 | 返回面板 | 返回面板 |

- **碰拳**：从两人里先按下的那一刻起，0.6 秒内另一人也按下就算碰到；庄家在 0.9 秒后结算。只碰到一个人就
  配对；没碰到人提示"没碰到对手"；同一时刻有好几个人在碰拳、分不清谁和谁时提示"人太多，再试一次"。
  电脑选手不参与碰拳。
- **选择对手**只列出此刻空闲且在线的人，真人在前、电脑选手在后，显示昵称。
- 挑战 20 秒无人应战自动作废；对决中一方断线 15 秒，对决作废，双方都不扣牌。
- 庄家屏幕显示汇总（入座、在线、对决中、已离场），"选手名单"里能看到每个人的昵称、状态、星星和剩余手牌数，
  但不显示具体是哪几张牌，可以放在明处。页脚显示看板是否已连上电脑。
- 设置页显示本机昵称、Wi-Fi、电脑服务地址和设备编号；"重新配网"会重启进入配网。
- 登记页与配网页屏幕常亮；其他页面 60 秒无操作变暗，第一下按键只负责点亮，有新事件时也会自动点亮。

## 电脑服务与看板

`tools/kj_hub` 是一个只用 Python 标准库的电脑服务，详见 [电脑服务说明](tools/kj_hub/README.zh_CN.md)：

- **联机中继**：所有设备只和电脑通信（UDP），电脑按设备转发游戏帧；庄家仍是唯一的裁判。
- **扫码登记昵称**：设备显示二维码，手机打开电脑上的登记页；昵称只存在电脑的数据目录里
  （默认 `~/kj-hub-data`），设备用自己的昵称字库显示，显示不了的字在登记时就会提示换掉。
- **看板**：浏览器打开 `http://127.0.0.1:47180/board`。全场公告板、每位选手一张卡片（昵称可以直接改，
  会同步到设备）、开始 / 结束 / 新一局 / 增减电脑选手 / 清空 / 移出、可选时限、对局记录、一键遮挡（H 键）、演示。
  多个赌局时可以在顶部切换。看板只允许这台电脑打开；别的电脑或平板要用服务启动时打印的带令牌链接。
- **采集与导出**：每一局的选手状态和事件都写成 JSONL；服务首页 `http://127.0.0.1:47180/` 可以导出每局的
  选手结果、对局事件和昵称登记表（CSV，Excel / WPS 直接打开中文不乱码）。

没有电脑服务时，庄家仍可以用 USB 线接电脑，用 Chrome / Edge 直接打开 `tools/kj_board/index.html`，点"连接
庄家设备（USB）"看看板；但选手设备之间的联机必须经过电脑服务。

## 工作原理

```text
                                   ┌──────────── 电脑服务 tools/kj_hub ────────────┐
选手设备 ──UDP 47101 信封+游戏帧──► │ 按 MAC 中继 · 发现 · 昵称登记 · 记录 · 看板    │ ◄─HTTP 47180─ 手机（登记页）
   ▲                                │                                               │ ──SSE──► 浏览器看板
   └──────── 庄家的视图 / 信标 ◄─────┤                                               │
庄家设备 ──UDP（游戏帧）+ TCP 47103（"@KJ {json}" 看板行 / "@KJ start" 命令）────────┘
```

- **一份固件，两种角色。** 庄家运行规则引擎（`main/kj_rules.c`），是唯一可信状态。选手只收到自己
  座位的视图；双方都扣牌之前，对手的牌不会发给任何人。
- **网络。** 设备以 STA 连现场 Wi-Fi，找不到电脑服务时每秒广播一次 DISCOVER（有上次的地址就交替单播），
  电脑服务回 OFFER 并每 2 秒广播一次。游戏帧（`main/kj_proto.h`，≤ 64 字节）套上 24 字节的 hub 信封
  （`main/kj_hubproto.h`）经电脑转发：庄家的信标扇出给所有选手，选手的心跳与请求只发给庄家。
- **可靠性在应用层**（`main/kj_server.c`、`main/kj_client.c`）：请求带序号与开机号，每 250 ms 重发直到
  视图确认；庄家按开机号去重，并重发视图直到心跳确认版本号；视图带庄家的开机号（epoch），选手丢弃同一
  次开机里版本号倒退的旧视图（UDP 会乱序）。碰拳请求带"在路上多久"，庄家据此还原按下时刻。
- **昵称。** 电脑服务的登记表说了算：设备开机时把本机保存的昵称报上去（登记表丢了可以补回），电脑回复
  最新的昵称；别人的昵称按（赌局号、编号）向电脑查询并缓存。庄家的看板行带上每个座位的 MAC，电脑据此
  把座位对上昵称。
- **配网。** 独立的开机模式：设备以 APSTA 开热点，网页服务 + 通配 DNS（弹窗认证），新的 Wi-Fi 先实际
  连上一次才保存，然后重启进入游戏（配网与游戏的内存峰值隔开）。
- **持久化。** 庄家在状态变化后把紧凑快照写入 NVS，掉电重启后恢复赌局；进行中的碰拳 / 挑战 / 对决作废，
  扣下的暗牌退回手中。Wi-Fi、昵称、上次的电脑地址也存在 NVS。
- **测试。** 主机测试覆盖规则、碰拳配对、协议、hub 线协议与客户端、DNS、配网表单，以及两套多设备仿真：
  直连 25% 丢包，和经 hub 中继每跳 10% 丢包、重复、乱序，中途重启选手、电脑服务和庄家。电脑服务有自己的
  单元与集成测试；C 与 Python 两边的线协议用同一份黄金向量（`tests/data/kj_hub_vectors.txt`）逐字节对照。

## 编译与刷机

```bash
source <ESP-IDF v5.5.3 路径>/export.sh
./tools/validate.sh            # 主机测试 + 固件编译 + 合并镜像校验
```

从 `0x0` 刷入校验过的合并镜像会**清空设备上保存的数据**（Wi-Fi、昵称、庄家保存的赌局），之后需要重新配网：

```bash
python -m esptool --chip esp32c3 -p <串口> -b 460800 write-flash 0x0 build/FoloToy-AI-Passport-full.bin
```

只更新程序、保留已保存的数据时，只写应用分区（用 `validate.sh` 归档在 `build/firmware/<sha256>/` 里的文件）：

```bash
python -m esptool --chip esp32c3 -p <串口> -b 460800 write-flash 0x10000 build/firmware/<sha256>/FoloToy-AI-Passport.bin
```

开发时可以在本地（不进仓库的）`sdkconfig` 里设置 `CONFIG_KJ_DEV_WIFI_SSID` / `CONFIG_KJ_DEV_WIFI_PASSWORD`，
没配过网的设备会直接连这个 Wi-Fi；`menuconfig` 的 Limited RPS 菜单里还可以把 Wi-Fi 省电改成 MIN_MODEM（省电但每个包
延迟更大，需要实测）。

开发辅助：

| 命令 | 用途 |
| --- | --- |
| `python3 tools/kj_hub/hub.py` | 电脑服务（联机、登记、看板、记录）。 |
| `python3 tools/render_kj_preview.py` | 用真实界面代码把每个设备页面渲染到 `build/kj_preview/shots/`，并报告 LVGL 内存池峰值；`--sheet` 生成 README 的拼图。需要先编译一次固件得到 `managed_components/`。 |
| `python3 tools/gen_kj_fonts.py check` | 校验已提交的字体覆盖全部界面文字与昵称字符集（`validate.sh` 会运行）。 |
| `python3 tools/gen_kj_fonts.py generate ...` | 修改 `main/kj_strings.h` 或 `tools/kj_charset.py` 后重新生成字体，见 [assets](assets/README.zh_CN.md)。 |
| `python3 tools/kj_charset.py 小明` | 检查一个昵称设备能不能显示。 |

## 限制与待验证项

- **没有在实机上验证过：** Wi-Fi 联机的延迟与稳定性、多台设备时的空中占用与续航（Wi-Fi 常开，估计 4~5 小时）、
  配网热点在各家手机上的弹窗表现、微信扫一扫打开局域网网页（iOS 上可能需要允许微信访问"本地网络"，
  不行就用手机相机扫码）、碰拳在真人手上的时间差。
- 电脑服务是单点：电脑睡眠或退出，全场暂停；重新启动后设备自动重连，庄家的赌局在设备上，不会丢。
- 需要设备之间（经电脑）互通的 2.4 GHz Wi-Fi；开了 AP 隔离、需要网页认证的网络不行。路由器不转发广播时，
  在配网网页的"高级"里填电脑的 IP，或启动服务时加 `--sweep <网段>`。
- 昵称只能用设备字库里有的字：可打印 ASCII、`·`、GB2312 的 6763 个汉字和少量人名常用字；表情符号和繁体字不行。
- 这一版不再支持不经电脑的 ESP-NOW 直连；两种固件之间不能混用（电脑服务会提示版本不同）。
- 一台庄家最多 128 个座位；选择庄家角色后，重启设备才能改选。
